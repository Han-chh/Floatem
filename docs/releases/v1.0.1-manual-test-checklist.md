# Floatem v1.0.1 Sandbox manual test checklist

> Historical checklist for build 32. It must not be used to approve the current release. Use the [v1.0.8 build 47 checklist](./v1.0.8-manual-test-checklist.md) instead.

Test the installed Release build at `/Applications/Floatem.app`. Record the macOS version, hardware, commit, app version/build, and result for every failed item.

## 1. Installation and product identity

- [ ] Finder shows Floatem with the expected icon and name.
- [ ] About/Finder information reports version `1.0.1` and build `32`.
- [ ] The app launches without Xcode, Node.js, pnpm, or a development server running.
- [ ] No Floatem Widget appears in the macOS Widget gallery.
- [ ] Activity Monitor shows only the Floatem app and its normal WebKit processes; no Widget extension launches.

## 2. Fresh-install startup behavior

Back up existing data before simulating a fresh install. Quit Floatem, turn off its Login Item, and temporarily move both `~/Library/Group Containers/group.com.hankch.floatem` and `~/Library/Containers/com.hankch.floatem` aside. Restore them after this section if the data is needed.

- [ ] The first user-initiated launch opens the Main Window.
- [ ] “Open Floatem at login” is off by default.
- [ ] With “Open Floatem at login” off, the Main Window displays the launch-at-login explanation dialog in the app's selected language.
- [ ] Switch between English and Simplified Chinese, relaunch after each switch, and verify the title, explanation, buttons, and “don't show again” checkbox are fully localized.
- [ ] Choose “Not Now” without checking “don't show again”, quit completely, relaunch, and verify the dialog appears again.
- [ ] Choose “Not Now” with “don't show again” checked, quit completely, relaunch twice, and verify the Main Window opens without the dialog.
- [ ] Reset the app's fresh-install data, choose “Enable Launch at Login”, and verify the setting changes immediately and the dialog does not appear on later user launches.
- [ ] Floatem is absent from System Settings > General > Login Items until the user enables it.
- [ ] The menu-bar item appears and its menu can show the Main Window and quit the app.
- [ ] Quitting and launching from Finder, Spotlight, or `/Applications` opens the Main Window.
- [ ] Closing/hiding the Main Window leaves the menu-bar app usable.

## 3. App Group storage and persistence

- [ ] Create a Note and a Todo, quit Floatem completely, relaunch it, and verify both remain.
- [ ] Change language, theme, time zone, time format, animation, reminder sound, and shortcut; relaunch and verify all settings remain.
- [ ] Verify data files are written under `~/Library/Group Containers/group.com.hankch.floatem/SharedData`.
- [ ] Launch Floatem while offline and verify the bundled interface still loads; reconnect and verify no window-content recovery error appears.
- [ ] Relaunch after disconnecting the network and verify all local content remains available.
- [ ] Upgrade over the previous Floatem build and verify existing Notes, Todos, groups, reminders, and window placement are retained.
- [ ] Confirm no unexpected file-access or Sandbox denial dialog appears.

## 4. Notes

- [ ] Create, edit, reorder, group, filter, recolor, collapse, and delete Notes.
- [ ] Test bold, italic, underline, text color, clear formatting, undo, redo, select all, copy, and paste.
- [ ] Paste multi-line plain text and rich text; verify no content is lost or duplicated.
- [ ] Edit Chinese text with an IME and verify the candidate window and composition behave correctly.
- [ ] Quit during/after editing and verify the latest saved text returns.

## 5. Todos and reminders

- [ ] Create, edit, complete, reopen, group, filter, bulk edit, change date, and delete Todos.
- [ ] Add reminders using quick times and a custom time.
- [ ] On the first launch, grant notification permission; then create a reminder and verify it is scheduled.
- [ ] Run the test notification with sound on and off.
- [ ] Deny notification permission, verify the error is understandable, and verify the System Settings shortcut works.
- [ ] Re-enable notifications in System Settings and verify reminders work again.
- [ ] Click a delivered reminder and verify Floatem opens the correct Todo.
- [ ] Quit and relaunch; verify future reminders remain scheduled and expired reminders display correctly.

## 6. Floating and desktop-pinned NSPanel cards

- [ ] Drag a Note out into a floating card; edit, resize, move, keep on top, and dock it back.
- [ ] Repeat the same flow for a Todo, including completion and reminder editing.
- [ ] Pin a Note and a Todo to the desktop and verify both use app-owned NSPanel windows.
- [ ] Verify desktop cards stay at the desktop level, remain editable, and do not appear as system Widgets.
- [ ] Quit and relaunch Floatem normally; verify pinned cards restore with current content.
- [ ] Delete a pinned entity and verify its desktop panel does not return after relaunch.
- [ ] Drag out and dock back the same card 20 times; verify there is no visible slowdown, duplicated panel, or runaway WebKit process growth.
- [ ] Open 10 floating cards and verify editing remains isolated between cards.

## 7. Login Item and silent login launch

- [ ] With no pinned cards, enable “Open Floatem at login” and confirm Floatem appears in System Settings > General > Login Items.
- [ ] Log out and back in. Confirm the menu-bar item, global shortcut, and reminder services initialize without showing or focusing the Main Window.
- [ ] Disable the Login Item, then simulate or inspect a login-item-marked launch and confirm it cannot stay silent when the real system permission is off.
- [ ] After a silent login launch, use the global shortcut and confirm the Main Window opens and focuses correctly.
- [ ] Pin desktop cards, log out and back in, and verify the cards restore while the Main Window stays hidden.
- [ ] Disable “Open Floatem at login”, log out and back in, and verify Floatem does not launch.
- [ ] Disable the item directly in System Settings and verify Floatem reports the real system state instead of showing a false enabled state.
- [ ] Re-enable it from Floatem and verify any required-approval guidance opens the correct System Settings page.

## 8. Global shortcut, menu bar, clipboard, and color picker

- [ ] Verify the default global shortcut opens/hides Floatem from another app and from another Space.
- [ ] Record a new valid shortcut and verify it persists after relaunch.
- [ ] Try a conflicting or invalid shortcut and verify the previous working shortcut remains registered.
- [ ] Verify menu-bar Show/Hide and Quit commands in both English and Simplified Chinese.
- [ ] Copy and paste between Floatem and TextEdit/Safari in both directions.
- [ ] Use the screen color picker on Floatem and another application; verify the chosen color is applied.

## 9. Windows, displays, Spaces, and fullscreen

- [ ] Resize the Main Window through compact, regular, and expanded sizes; verify controls remain reachable.
- [ ] Move the Main Window and floating cards between two displays and relaunch.
- [ ] Disconnect the secondary display and verify every restored window is clamped onto a visible screen.
- [ ] Change display scaling/resolution and verify windows remain inside the visible frame.
- [ ] Switch Spaces and verify the configured floating/desktop card behavior.
- [ ] Test beside a fullscreen app and verify cards do not steal focus unexpectedly.

## 10. Final release checks

- [ ] Run for at least 30 minutes while editing Notes, Todos, reminders, and floating cards; observe no crash or persistent CPU spike.
- [ ] Review Console for repeated Sandbox denials involving App Group storage, login items, notifications, clipboard, WebKit, or screen access.
- [ ] Verify quitting Floatem terminates its app-owned panels and WebKit processes.
- [ ] Relaunch once more and verify data, settings, shortcut, reminders, and intended desktop cards all recover.
- [ ] Record every failure with reproduction steps and mark the build No-Go until all P0/P1 failures are fixed and retested.
