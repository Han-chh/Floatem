# Floatem v1.0.8 (build 47) manual release checklist

Use this checklist for the installed signed Release/TestFlight build, not the unsigned local Debug build. Record macOS version, hardware, commit, installation source, and result for every failed item.

## 1. Product identity and installation

- [ ] Finder/About reports `Floatem`, version `1.0.8`, and build `47`.
- [ ] The Bundle ID is `com.hankch.floatem`, Team is `85923Q9JUG`, and signed entitlements contain only the intended App Group `group.com.hankch.floatem`.
- [ ] The app launches without Xcode, Node.js, pnpm, or a Vite server.
- [ ] The icon and product name are correct in Finder, Dock, Launchpad, menu bar, notifications, and About.
- [ ] No WidgetKit extension or Floatem Widget appears.

## 2. Fresh-install help entry

Back up user data before simulating a fresh installation. Quit Floatem, disable its Login Item, and move the Floatem App Group/container directories aside rather than deleting them.

- [ ] The first direct launch opens the Main Window.
- [ ] The upper-right `?` help button has a visible but non-blocking animated highlight.
- [ ] A callout explains that the highlighted button opens feature help and the interactive guide.
- [ ] Chinese and English copy are complete, legible, and not clipped.
- [ ] **Open guide** acknowledges the hint and opens the existing help dialog.
- [ ] **Later** acknowledges and dismisses the hint without opening help.
- [ ] Escape dismisses the callout without trapping keyboard focus.
- [ ] After either action, quit and relaunch twice; the first-install callout does not return.
- [ ] Reset ordinary settings from the Settings page; the completed first-install hint does not return.
- [ ] Upgrade from a pre-1.0.8 settings document; the hint does not appear unexpectedly.
- [ ] The launch-at-login explanation does not compete with the first-install help callout in the first session.

## 3. Help and interactive guide

- [ ] Open help manually from the upper-right `?` after onboarding.
- [ ] Review Overview, Notes, Todos, Floating cards, Settings, and Shortcuts in both languages.
- [ ] Complete all seven interactive-guide feature workflows.
- [ ] Verify instructions, highlights, arrows, animations, progress, Previous/Next behavior, and completion dialog remain readable at compact and expanded window sizes.
- [ ] Verify practice Notes/Todos/groups are removed and temporary UI/settings changes are restored after finish or exit.
- [ ] Verify floating-card guidance distinguishes ordinary floating cards from desktop-pinned cards.

## 4. Notes and Todos

- [ ] Create, edit, reorder, group, recolor, filter, collapse/expand, and delete Notes.
- [ ] Test rich-text formatting, toolbar collapse, undo/redo, select all, clipboard, multiline paste, and Chinese IME composition.
- [ ] Create, edit, reorder, group, filter, date, complete/reopen, bulk edit, and delete Todos.
- [ ] Verify Enter quick-entry flow and visible submit control.
- [ ] Add quick/custom reminders; verify permission handling, sound on/off, delivery, and deep-link opening of the intended Todo.
- [ ] Quit and relaunch; verify Notes, Todos, groups, settings, future reminders, and current content persist.

## 5. Floating and desktop-pinned cards

- [ ] Drag both a Note and Todo into floating editing cards.
- [ ] Edit, resize horizontally/diagonally, move across displays/Spaces, keep above ordinary windows, fold where supported, and drag/close back into the list.
- [ ] Pin a Note and Todo to the desktop and verify they remain editable app-owned panels rather than widgets.
- [ ] Quit/relaunch and confirm current content and placement restore.
- [ ] Delete a pinned entity and confirm its panel does not return.
- [ ] Disconnect a secondary display or change scaling and confirm restored windows are clamped into a visible frame.
- [ ] Repeatedly float/dock one card and open multiple cards; verify no duplicate panels, cross-card edits, or runaway WebKit process growth.

## 6. Login Item and launch behavior

- [ ] Launch at login is off by default on a fresh installation.
- [ ] On a later direct-launch session, verify the localized launch-at-login explanation can enable the feature, dismiss once, or suppress future prompts.
- [ ] Toggle **Open Floatem at login** and verify the real state in System Settings > General > Login Items.
- [ ] Log out/in with the feature enabled. Floatem initializes menu bar, shortcut, reminders, and desktop cards without showing/focusing the Main Window.
- [ ] Summon the silently launched app with the global shortcut.
- [ ] Disable the item in Floatem and directly in System Settings; verify the UI reports the real state and provides approval guidance when required.
- [ ] Finder, Dock, Spotlight, reopen, menu-bar Show/Hide, deep-link, and Quit behaviors match their intended visible/silent launch paths.

## 7. Settings, appearance, and accessibility

- [ ] Verify all six themes, transition styles, speeds, particles, time zone, 12/24-hour format, language, default section, shortcut recording, reminder sound, and Restore defaults.
- [ ] Verify current values survive relaunch and Restore defaults preserves completed onboarding markers.
- [ ] Check text contrast, truncation, tooltips, focus, click targets, and animations at compact/regular/expanded sizes.
- [ ] Verify the About page reports v1.0.8, the current feature/privacy description, contact information, copyright, and “Don't lose thoughts. Float'em.”

## 8. Release and TestFlight

- [ ] Xcode Validate App succeeds with no blocking signing, entitlement, privacy, encryption, or asset errors.
- [ ] Upload build 47 and wait until App Store Connect finishes processing.
- [ ] Confirm export compliance does not ask for non-exempt encryption documentation.
- [ ] Install from TestFlight on at least one Apple Silicon Mac and, if available, one Intel Mac.
- [ ] Repeat the fresh-install help path, core Note/Todo path, floating/desktop card path, reminder path, shortcut path, and login/restart path using the processed TestFlight build.
- [ ] Confirm Beta description, “What to Test,” screenshots, privacy answers, support/contact details, and reviewer instructions match the actual v1.0.8 build.
- [ ] Record every failure. Any crash, data loss, install/launch/signing failure, broken onboarding, or core workflow failure is No-Go until fixed and retested with a new build number.
